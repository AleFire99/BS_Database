
Both databases are opened read-only. Family names in the legacy database are English machine translations; they are mapped to the new families through the glossary ([family_legacy_en.csv](../../data/glossary/family_legacy_en.csv)), the new English names and the English aliases. The legacy database has no Japanese names, effects, images or products, so those cannot be compared.

Labels: **new data** (the new build has more or better data), **normalization** (the same fact under another spelling or mapping), **legacy bug** (the legacy value is wrong or lossy) and **unexplained** (to investigate).

## Summary

- All 96 numbers only in the legacy database are flip cards that the new build stores as two numbers `(A)` and `(B)`: nothing was lost.
- Cost and card type are identical on all 6,277 shared numbers.
- No category is labelled **unexplained** in this run.
- The "legacy bug" labels on families (legacy_merged, name_collision, legacy_extra) are inferred from family counts and the glossary, not from a page-by-page check.
- The count_same family category compares only the number of families, because most legacy English names are missing from the glossary; it can hide real differences.
- Legacy and new English names come from different translators, so they are only split into same, folded, close and far.
